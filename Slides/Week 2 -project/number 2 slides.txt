**Slide 2 — Why VIX + S&P 500, and not the things I originally wanted**

The honest version of the dataset reasoning. I went through three candidates:

1. **T-bills + S&P 500.** Moody and Saffell's original setup. Tempting because it's the canonical financial-RL paper and the comparison would be easy. But T-bills don't carry the memory structure my thesis actually needs. They drift, they don't *encode regime*.

2. **VIX-only, predict next VIX.** Clean, single series. The problem is that pure forecasting has no sequential consequence — a wrong call at t doesn't change my situation at t+1. So the supervised baseline would trivially be at least as good, and the RL framing earns nothing. Adaptive Stacking has nothing to prove there.

3. **VIX as observation, S&P 500 as the underlying for positions.** This is what landed in the proposal. The reason: VIX has memory baked into its construction. It reflects the decay tail of crashes that happened weeks or months ago. A spike from a Fed announcement six weeks back still shapes today's level. That is *exactly* the sparse-signal-in-noisy-history pattern Adaptive Stacking is built for — most days the VIX print is noise, a few historic days are the entire story.

Picking VIX is therefore not a dataset preference. It's the most structurally honest test of the central assumption Adaptive Stacking depends on (κ ≪ k*). If sparsity holds anywhere in finance, it holds here.

**Slide 3 — The research question, framed in one sentence**

Adaptive Stacking works in T-Maze, MiniGrid-Memory, Rubik's Cube, FetchReach. Those are stationary, episodic, sparse-reward, well-defined-informative-observation environments. Financial markets are *none* of those things. They are non-stationary, continuous, dense-reward, and the informative observations are often diffuse rather than concentrated.

So the research question is: **does the memory-action mechanism that works in those controlled benchmarks transfer to noisy, non-stationary financial time-series?**

This is the same story that played out for AI more broadly. Game AI looked unbeatable on chess and Go and Atari — fully observable, well-defined, controlled. The same systems struggled the moment they walked into partially observable real-world settings. Adaptive Stacking is at the same crossroads, but specifically for *memory*. It has been validated in the controlled half of the world. Whether it survives the messy half is the open question. That's what I'm here to find out.

**Slide 4 — Three research questions, stacked on top of each other**

The comparison is a three-step staircase. Each step changes one variable. The result of step n sets up step n+1.

**RQ1 — Does RL beat supervised on this task at all?**
LSTM forecaster + threshold rule vs. memoryless PPO. If supervised wins here, the sequential framing of RL is adding nothing on this dataset, and that's a publishable finding in its own right.

**RQ2 — Does fixed memory beat no memory?**
Memoryless PPO vs. PPO + Frame Stacking, k ∈ {3, 5, 10, 20}. Sanity check. Prior work already says yes for partially observable tasks. Replicating it on financial data is a floor.

**RQ3 — Does *learned* memory beat *fixed* memory at matched memory budget?**
Frame Stacking at k vs. Adaptive Stacking at κ = k, for each k in the sweep. **This is the primary contribution.** Same comparison Nangue Tasse et al. ran on T-Maze, now run on a non-stationary financial stream where the sparsity assumption is far less obvious.

**Slide 5 — The four configurations on one slide**

| # | Configuration            | What it observes               | Memory mechanism                  | Answers   |
|---|--------------------------|--------------------------------|-----------------------------------|-----------|
| 1 | Supervised (LSTM)        | VIX history → forecast S&P     | Hidden state (truncated BPTT)     | RQ1       |
| 2 | PPO no-memory            | Current VIX only               | None (Frame Stacking with k=1)    | RQ1, RQ2  |
| 3 | PPO + Frame Stacking     | Last k VIX values, FIFO        | Passive sliding window            | RQ2, RQ3  |
| 4 | PPO + Adaptive Stacking  | κ slots, agent chooses what    | Learned memory action             | RQ3       |

Same PPO base for configurations 2–4. Same network widths. Same hyperparameters. The only variable that moves between Frame Stacking and Adaptive Stacking is *who decides what to remember*. That's the whole point.

Buy-and-hold gets reported alongside, as a financial sanity baseline. If a trained agent can't beat doing nothing, the agent hasn't earned its keep regardless of how the memory comparison turns out.

**Slide 6 — The interaction loop, plain English**

Every day:
1. The environment hands the agent today's VIX (and, for the stacked agents, some history).
2. The agent picks a position for tomorrow: short, flat, or long S&P 500.
3. Tomorrow happens. S&P 500 moves by some return r.
4. The agent gets reward = position × r, minus a small transaction cost if it just flipped from yesterday's position.
5. Repeat.

Over time, the agent learns to map "what the volatility regime looks like (and how it's looked lately)" to "what side of the market to be on." If Adaptive Stacking is doing what it claims, the slots it keeps should cluster around VIX spikes and regime transitions — not be uniformly spread across the trailing window.

That last bit is a diagnostic I plan to actually look at, not just claim.

**Slide 8 — Risks I already named in the proposal**

Three things that could go wrong, ranked by how worried I should be:

1. **The sparsity assumption (κ ≪ k*) may not hold in financial data.** Adaptive Stacking's efficiency argument depends on the relevant past being *concentrated*. Financial signals are often *diffuse* — many marginally informative observations, not a few decisive ones. If that's the case here, AS may not beat Frame Stacking at any κ. That would be a *negative* result. A negative result is still a contribution — it tells the next person not to try this — but it's the result I want to be most honest about ahead of time.

2. **The convergence theorem for Adaptive Stacking assumes a stationary k*-Markov environment.** Financial returns are not stationary. Walk-forward retraining is a partial mitigation, not a fix. I'm not going to claim theoretical guarantees in this setting. The empirical comparison has to stand on its own.

3. **Compute.** Four stack sizes × two memory mechanisms × multiple seeds × walk-forward windows is a lot of training. Contingency in the proposal: drop seed count from 5 → 3 first, then trim the sweep grid from {3,5,10,20} → {3,10,20}. Keep the *comparison structure* intact at the cost of statistical confidence on each data point.
